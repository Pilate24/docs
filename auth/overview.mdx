GlobeTrotter gives you two primary ways to sign in — email/password credentials or Google OAuth — plus one-click demo accounts for instant exploration. Once authenticated, your session is stored in a secure HTTP-only cookie and automatically validated on every protected page.

## User Roles

Every GlobeTrotter account is assigned one of two roles at creation time.

| Role | Access |
|------|--------|
| USER | Full access to your own trips, itinerary builder, discovery, profile, and public trip sharing |
| ADMIN | All USER access, plus the admin analytics dashboard at `/admin` |

## Session Flow

<Steps>
  <Step title="Sign in at /login">
    Navigate to `/login` and authenticate with your chosen method — email/password, Google OAuth, or a demo one-click button.
  </Step>
  <Step title="Session cookie is issued">
    The server validates your credentials and writes a secure HTTP-only `gt_session` cookie to your browser. No tokens are stored in `localStorage` or exposed to JavaScript.
  </Step>
  <Step title="Access protected pages">
    Protected routes — `/itinerary-builder`, `/profile`, and `/admin` — check for a valid `gt_session` cookie on every request. Authenticated users proceed; unauthenticated users are redirected to `/login`.
  </Step>
  <Step title="Retrieve the current user">
    Call `GET /api/auth/me` at any time to retrieve the active session user's `id`, `email`, `name`, and `role`. A `401` response means no session is present.
  </Step>
</Steps>

### `/api/auth/me` Response

```json
{
  "success": true,
  "data": {
    "id": "1",
    "email": "user@globetrotter.com",
    "name": "Alex Traveler",
    "role": "USER"
  },
  "message": "User session active",
  "error": null
}
```

When no session is active, the endpoint returns:

```json
{
  "success": false,
  "data": null,
  "message": "",
  "error": "No active session"
}
```

## Protected Routes

The following route prefixes require an active session. Middleware intercepts unauthenticated requests and redirects to `/login`.

| Route Prefix | Who Can Access |
|---|---|
| `/itinerary-builder/*` | Any authenticated user (USER or ADMIN) |
| `/profile/*` | Any authenticated user (USER or ADMIN) |
| `/admin/*` | Authenticated users with the ADMIN role |

<Note>
  Route protection is enforced at the middleware layer via the `gt_session` cookie check. Even direct API calls to protected endpoints require an active session and will receive a `401 Unauthorized` response if none is present.
</Note>

## API Authentication

All GlobeTrotter API endpoints — except `GET /api/public/trips/:slug` — require an active session. Unauthenticated requests receive a `401` response with the following envelope:

```json
{
  "success": false,
  "data": null,
  "message": "",
  "error": "Unauthorized"
}
```

<Warning>
  Never share your session cookie or expose it in client-side code. If you suspect a session has been compromised, sign out immediately from `/profile` to invalidate it.
</Warning>
