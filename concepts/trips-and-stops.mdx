GlobeTrotter organises every travel plan around a three-level hierarchy: a **Trip** is the top-level container that holds all your high-level settings (dates, budget, visibility); each Trip contains one or more **Stops** representing individual city visits with their own arrival and departure dates; and each Stop holds **Activities** — the specific experiences you schedule during that city stay. Understanding this model will help you plan, edit, and share itineraries with confidence.

## Trips

A Trip is the root of your travel plan. When you create a trip, you define its title, date range, budget, and currency. GlobeTrotter auto-generates a URL-safe slug from the title (e.g., `summer-euro-trip-2026-a8f9`) which is used for public sharing once you make the trip visible.

| Field | Required | Constraints | Notes |
|---|---|---|---|
| `title` | Yes | 3–100 characters | Used to auto-generate the sharing slug |
| `startDate` | Yes | ISO date string | Must be ≤ `endDate` |
| `endDate` | Yes | ISO date string | Must be ≥ `startDate` |
| `targetBudget` | No | Number, default `0` | Used for budget variance calculation |
| `currency` | No | String, default `USD` | Applied to all cost displays |
| `description` | No | Free text | General notes and group reminders |
| `coverImageUrl` | No | URL string | Hero image shown on trip cards |
| `isPublic` | No | Boolean | Enables the public vanity URL |
| `status` | Auto | Enum | Set automatically based on dates |

### Trip Statuses

Trip status is derived automatically from the current date relative to the trip's date range. It progresses through the following stages:

| Status | Meaning |
|---|---|
| `DRAFT` | Trip is created but dates or details are incomplete; not yet ready for travel |
| `UPCOMING` | Trip is fully planned and the start date is in the future |
| `ONGOING` | Today's date falls within the trip's start and end dates |
| `COMPLETED` | The trip's end date has passed |

## Stops

Each Stop represents a city visit within your trip. Stops are sequential — they are ordered by `stopOrder` and their dates must be continuous and non-overlapping. When you add a stop, you specify the destination, arrival and departure dates, how you're getting there, and how much accommodation costs per night.

| Field | Required | Constraints | Notes |
|---|---|---|---|
| `destination` | Yes | City from the catalogue | Links to the destinations catalogue |
| `arrivalDate` | Yes | ISO date string | Must be ≥ trip `startDate` |
| `departureDate` | Yes | ISO date string | Must be ≥ `arrivalDate` |
| `stopOrder` | Yes | Integer, min `1` | Determines sequence in the itinerary |
| `transportMode` | No | Enum (see below) | How you're arriving at this city |
| `transportCost` | No | Number | Cost for the leg into this city |
| `accommodationCost` | No | Number | Nightly lodging rate for this stop; multiplied by the number of nights to compute total lodging cost |

### Transport Modes

| Mode | Description |
|---|---|
| `FLIGHT` | Arrival by air |
| `TRAIN` | Arrival by rail |
| `BUS` | Arrival by coach or intercity bus |
| `DRIVE` | Arrival by personal or rental vehicle |
| `FERRY` | Arrival by boat or ferry service |
| `NONE` | No transport cost (e.g., starting city) |

## Activities

Activities are the day-level building blocks of a stop. Each activity is scheduled to a specific stop and optionally to a specific date and start time within that stop's date range. You can use the curated activity catalogue or create custom entries.

| Field | Required | Notes |
|---|---|---|
| `title` | Yes | Activity name (catalogue title or custom) |
| `category` | Yes | One of: `SIGHTSEEING`, `ADVENTURE`, `FOOD`, `CULTURE`, `RELAXATION`, `NIGHTLIFE` |
| `estimatedCost` | No | Default cost from the activity catalogue |
| `customCost` | No | Overrides `estimatedCost` for budget calculations |
| `duration` | No | Duration in minutes |
| `scheduledDate` | No | The specific day within the stop's date range |
| `startTime` | No | Time of day the activity begins |

## Data Hierarchy

The following diagram shows how a complete multi-city itinerary is structured in GlobeTrotter:

```text
Trip: "Summer Euro-Trip 2026"
├── startDate: 2026-09-12   endDate: 2026-09-24
├── targetBudget: $3,500    currency: USD
│
├── Stop 1 — Paris, France  (Sep 12 → Sep 15)
│   ├── transportMode: FLIGHT    transportCost: $480
│   ├── accommodationCost: $120/night  (3 nights = $360)
│   ├── Activity: Louvre Museum       (Sep 12, 10:00) — CULTURE
│   ├── Activity: Eiffel Tower Tour   (Sep 13, 14:00) — SIGHTSEEING
│   └── Activity: Seine River Cruise  (Sep 14, 18:00) — SIGHTSEEING
│
├── Stop 2 — Rome, Italy  (Sep 15 → Sep 19)
│   ├── transportMode: TRAIN     transportCost: $95
│   ├── accommodationCost: $110/night  (4 nights = $440)
│   ├── Activity: Colosseum Tour      (Sep 15, 09:00) — CULTURE
│   ├── Activity: Vatican Museums     (Sep 16, 10:00) — SIGHTSEEING
│   └── Activity: Trastevere Food Walk (Sep 17, 19:00) — FOOD
│
└── Stop 3 — Barcelona, Spain  (Sep 19 → Sep 24)
    ├── transportMode: FLIGHT    transportCost: $110
    ├── accommodationCost: $120/night  (5 nights = $600)
    ├── Activity: Sagrada Família     (Sep 19, 11:00) — SIGHTSEEING
    ├── Activity: Park Güell          (Sep 20, 10:00) — SIGHTSEEING
    └── Activity: Gothic Quarter Walk (Sep 21, 15:00) — CULTURE
```

## Date Validation Rules

<Note>
GlobeTrotter enforces the following date constraints to keep your itinerary logically consistent:

- A stop's `arrivalDate` must be **on or after** the trip's `startDate`.
- A stop's `departureDate` must be **on or after** its own `arrivalDate`.
- The `arrivalDate` of Stop N+1 must be **on or after** the `departureDate` of Stop N — stops cannot overlap.
- All stop dates must fall **within** the overall trip `startDate` and `endDate` range.
</Note>
