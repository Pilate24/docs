The Public Trips API has two purposes: serving shared itinerary pages to any visitor without requiring a login, and letting authenticated users clone a public trip into their own account in one request. Both endpoints use a URL-safe `slug` that appears at `https://globetrotter.app/shared/{slug}` — the same link shown on the in-app share screen.

## GET /api/public/trips/:slug

Retrieve a full read-only view of a publicly shared trip by its slug. No authentication is required — any caller can access this endpoint.

### Path Parameters

<ParamField path="slug" type="string" required>
  The URL-safe slug from the trip's share link (e.g., `japan-autumn-tour-a8f9`). Slugs are auto-generated when a trip owner toggles their trip to public and appear in the share URL displayed on the itinerary share screen: `https://globetrotter.app/shared/{slug}`.
</ParamField>

### Example Request

```http
GET /api/public/trips/japan-autumn-tour-a8f9
```

### Response Codes

| Status | Meaning |
|--------|---------|
| `200`  | Success — returns the full public trip object including stops and activities |
| `404`  | No trip found for the given slug, or the trip exists but `isPublic` is `false` |
| `500`  | Internal server error |

<Info>
  Individual stop costs and overall budget figures are not included in the public trip response to protect the trip owner's financial data. To access budget details for a trip you own, use `GET /api/trips/:tripId/budget`.
</Info>

## POST /api/public/trips/:slug/clone

Clone a public trip into your own account. The operation is a complete deep copy — all stops, scheduled activities, and expense records are duplicated in a single atomic transaction. Authentication is required for this endpoint.

### Path Parameters

<ParamField path="slug" type="string" required>
  The URL-safe slug of the public trip you want to clone. Use the slug returned by `GET /api/public/trips/:slug` or taken directly from a share URL.
</ParamField>

### Request Body

No request body is required. Send the request with your active session cookie and an empty body.

```http
POST /api/public/trips/japan-autumn-tour-a8f9/clone
Cookie: next-auth.session-token=<your-session-token>
```

### Example Response

```json
{
  "success": true,
  "data": {
    "id": "f1e2d3c4-b5a6-7890-abcd-ef1234567890",
    "title": "Japan Autumn Tour (Clone)",
    "slug": "japan-autumn-tour-clone-b7c2",
    "status": "DRAFT",
    "clonedFromTripId": "d4e5f6a7-b8c9-0d1e-2f3a-4b5c6d7e8f9a",
    "isPublic": false,
    "startDate": "2025-10-01",
    "endDate": "2025-10-14"
  },
  "message": "Trip cloned successfully",
  "error": null
}
```

### Clone Behaviour

<Steps>
  <Step title="Lookup">
    GlobeTrotter resolves the slug and verifies the trip is publicly accessible. If the trip is private or does not exist, a `404` is returned before any write occurs.
  </Step>
  <Step title="Deep Copy (Atomic Transaction)">
    All trip stops, scheduled activities, and expense records are duplicated inside a single ACID database transaction. Either everything succeeds or nothing is written — there is no partial clone state.
  </Step>
  <Step title="Ownership Transfer">
    The new trip is assigned to your user account with `status` set to `DRAFT` and `isPublic` set to `false`. The `clonedFromTripId` field records the original trip's UUID for reference.
  </Step>
  <Step title="Slug Generation">
    A new unique slug is generated for your cloned trip automatically. Your clone gets its own independent share URL and does not share the original's slug.
  </Step>
</Steps>

<Note>
  Clones are fully independent copies. Edits you make to the cloned trip — changing dates, adding stops, adjusting the budget — have no effect on the original public trip or its owner's account.
</Note>

### Response Codes

| Status | Meaning |
|--------|---------|
| `201`  | Success — the cloned trip was created; returns the new trip object |
| `401`  | Not authenticated — sign in before calling this endpoint |
| `404`  | No public trip found for the given slug, or the trip is set to private |
| `500`  | Internal server error; any partial writes are rolled back automatically |

<Tip>
  After cloning, edit the `startDate` and `endDate` to match your own travel plans, then update the `status` to `UPCOMING` when you're ready. Use `PUT /api/trips/:id` to update trip details, or `PATCH /api/trips/:id/visibility` to make your clone public.
</Tip>
