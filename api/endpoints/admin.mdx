The Admin API surfaces platform-wide analytics and trip management data. Every endpoint under `/api/admin/*` requires the requesting account to hold the `ADMIN` role — this check is enforced server-side on every request. Regular `USER`-role accounts receive an HTTP `403` response regardless of whether they supply a valid session.

<Warning>
  These endpoints are restricted to ADMIN-role accounts only. Do not call admin API endpoints from end-user-facing code, client-side components, or public-facing pages. Treat all admin responses as sensitive operational data and handle them accordingly.
</Warning>

---

## GET /api/admin/metrics

Return platform-wide KPI metrics. Use this endpoint to power analytics dashboards, usage summaries, and growth trend charts.

### Authentication

Requires an active session for an account with the `ADMIN` role. Use the demo admin account (`admin@globetrotter.com` / `password123`) for local development and testing.

### Example Request

```http
GET /api/admin/metrics
Cookie: next-auth.session-token=<admin-session-token>
```

### Response Fields

<ResponseField name="totalUsers" type="number">
  Total number of registered user accounts on the platform, including both `USER` and `ADMIN` roles.
</ResponseField>

<ResponseField name="activeTrips" type="number">
  Count of trips currently in `UPCOMING` or `ONGOING` status across all user accounts.
</ResponseField>

<ResponseField name="avgStopsPerTrip" type="number">
  Mean number of city stops per trip across all trips on the platform. Reflects typical itinerary complexity.
</ResponseField>

<ResponseField name="totalTrips" type="number">
  Total number of trips ever created on the platform, across all statuses: `DRAFT`, `UPCOMING`, `ONGOING`, and `COMPLETED`.
</ResponseField>

<ResponseField name="trendingDestinations" type="array">
  Top destinations ranked by how many trips include a stop at that location.

  <ResponseField name="trendingDestinations[].name" type="string">
    Display name of the destination city or region.
  </ResponseField>

  <ResponseField name="trendingDestinations[].tripCount" type="number">
    Number of trips that include this destination as a stop.
  </ResponseField>
</ResponseField>

<ResponseField name="signupTrend" type="array">
  Daily new-user signup counts for the last 30 calendar days, ordered chronologically.

  <ResponseField name="signupTrend[].date" type="string">
    ISO 8601 date string (`YYYY-MM-DD`) representing the day.
  </ResponseField>

  <ResponseField name="signupTrend[].count" type="number">
    Number of new accounts created on that day.
  </ResponseField>
</ResponseField>

### Example Response

```json
{
  "success": true,
  "data": {
    "totalUsers": 5820,
    "activeTrips": 1430,
    "avgStopsPerTrip": 3.8,
    "totalTrips": 9200,
    "trendingDestinations": [
      { "name": "Tokyo", "tripCount": 640 },
      { "name": "Paris", "tripCount": 510 },
      { "name": "New York", "tripCount": 390 }
    ],
    "signupTrend": [
      { "date": "2026-05-01", "count": 42 },
      { "date": "2026-05-02", "count": 57 }
    ]
  },
  "message": "Metrics retrieved successfully",
  "error": null
}
```

### Response Codes

| Status | Meaning |
|--------|---------|
| `200`  | Success — returns the full platform metrics object |
| `401`  | No valid session — sign in with an ADMIN account before calling this endpoint |
| `403`  | Authenticated but the account does not have the `ADMIN` role |
| `500`  | Internal server error |

## GET /api/admin/trips

Return a paginated list of all trips across every user account on the platform. Use this endpoint for auditing, moderation, or support workflows.

### Authentication

Requires an active session with the `ADMIN` role.

### Query Parameters

<ParamField query="page" type="integer" default="1">
  Page number to retrieve. Use together with `limit` to navigate through large result sets.
</ParamField>

<ParamField query="limit" type="integer" default="20">
  Maximum number of trip records to return per page. Accepted range: 1–100.
</ParamField>

<ParamField query="search" type="string">
  Free-text filter applied against trip titles and owner email addresses. Partial matches are supported.
</ParamField>

<ParamField query="status" type="string">
  Restrict results to trips in a specific status. Accepted values: `DRAFT`, `UPCOMING`, `ONGOING`, `COMPLETED`.
</ParamField>

### Example Request

```http
GET /api/admin/trips?page=1&limit=20&status=DRAFT&search=euro
Cookie: next-auth.session-token=<admin-session-token>
```

### Example Response

```json
{
  "success": true,
  "data": {
    "trips": [
      {
        "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
        "title": "Eurotrip 2026",
        "userEmail": "traveler@example.com",
        "status": "DRAFT",
        "isPublic": false,
        "stopCount": 4,
        "createdAt": "2026-04-15T10:30:00Z"
      }
    ],
    "total": 214,
    "page": 1,
    "limit": 20
  },
  "message": "Trips retrieved successfully",
  "error": null
}
```

### Response Codes

| Status | Meaning |
|--------|---------|
| `200`  | Success — returns the paginated trip list and pagination metadata |
| `401`  | No valid session |
| `403`  | Authenticated but not an `ADMIN`-role account |
| `500`  | Internal server error |

<Info>
  The `total` field reflects the full count of matching records before pagination is applied — not the number of items returned on the current page. To determine the total number of pages, divide `total` by `limit` and round up.
</Info>

### Trip Status Reference

<Tabs>
  <Tab title="DRAFT">
    The trip is still being planned. It has not been activated by the owner and no travel has begun. Trips created via clone or from scratch always start in this status.
  </Tab>
  <Tab title="UPCOMING">
    The trip's `startDate` is in the future and the owner has marked it as active. The itinerary is finalised and travel is approaching.
  </Tab>
  <Tab title="ONGOING">
    The current date falls between `startDate` and `endDate`. The trip is actively in progress.
  </Tab>
  <Tab title="COMPLETED">
    The trip's `endDate` has passed. The trip is considered finished, though owners can still update details.
  </Tab>
</Tabs>
