GlobeTrotter's authentication endpoints handle user registration, login, session inspection, and logout. All routes live under the `/api/auth` prefix and are powered by NextAuth. Use these endpoints to establish a session before accessing any protected resource in the API.

<Note>
  All protected endpoints rely on an **HTTP-only session cookie** set by NextAuth. When calling the API from a browser client, include `credentials: 'include'` in every `fetch` call to ensure the cookie is forwarded automatically.
</Note>

---

## GET /api/auth/me

Retrieve the profile of the currently authenticated user. Use this endpoint to confirm an active session and read the user's id, email, display name, and role.

**Requires:** Active session cookie.

### Response fields

<ResponseField name="success" type="boolean" required>
  `true` when a valid session is found.
</ResponseField>

<ResponseField name="data" type="object">
  The authenticated user object.

  <Expandable title="data fields">
    <ResponseField name="id" type="string">
      UUID of the authenticated user.
    </ResponseField>
    <ResponseField name="email" type="string">
      The user's registered email address.
    </ResponseField>
    <ResponseField name="name" type="string">
      The user's display name.
    </ResponseField>
    <ResponseField name="role" type="string">
      Account role — either `USER` or `ADMIN`.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="message" type="string">
  `"User session active"` on success.
</ResponseField>

### Example response

```json title="200 OK"
{
  "success": true,
  "data": {
    "id": "uuid",
    "email": "user@example.com",
    "name": "Alex Traveler",
    "role": "USER"
  },
  "message": "User session active",
  "error": null
}
```

### Error responses

| Status | Condition |
|--------|-----------|
| `401`  | No active session cookie present |
| `500`  | Internal server error |

```json title="401 Unauthorized"
{
  "success": false,
  "data": null,
  "message": null,
  "error": "No active session"
}
```

## POST /api/auth/register

Create a new GlobeTrotter account with an email address and password. On success, the server returns the newly created user object. The new account is assigned the `USER` role by default.

### Request body

<ParamField body="email" type="string" required>
  A valid email address. Automatically trimmed and lowercased before storage. Must be unique across all GlobeTrotter accounts.
</ParamField>

<ParamField body="password" type="string" required>
  Account password. Minimum **8 characters**, must contain at least one letter and one number.
</ParamField>

<ParamField body="fullName" type="string" required>
  The user's full display name, shown throughout the application.
</ParamField>

### Example request

```json title="POST /api/auth/register"
{
  "email": "newuser@example.com",
  "password": "secure123",
  "fullName": "Jane Doe"
}
```

### Response fields

<ResponseField name="data" type="object">
  The newly created user object.

  <Expandable title="data fields">
    <ResponseField name="id" type="string">UUID of the new user.</ResponseField>
    <ResponseField name="email" type="string">Registered email address.</ResponseField>
    <ResponseField name="name" type="string">Display name from `fullName`.</ResponseField>
    <ResponseField name="role" type="string">`"USER"` — default role for all new accounts.</ResponseField>
  </Expandable>
</ResponseField>

### Example response

```json title="201 Created"
{
  "success": true,
  "data": {
    "id": "f4a1c2d3-...",
    "email": "newuser@example.com",
    "name": "Jane Doe",
    "role": "USER"
  },
  "message": "Account created successfully",
  "error": null
}
```

### Error responses

| Status | Condition |
|--------|-----------|
| `400`  | Validation failed — missing field, password too short, or malformed email |
| `409`  | Email already registered to an existing account |

```json title="409 Conflict"
{
  "success": false,
  "data": null,
  "message": null,
  "error": "An account with this email already exists"
}
```

## POST /api/auth/login

Authenticate with an existing email and password. On success, NextAuth sets an HTTP-only session cookie and returns the user object.

### Request body

<ParamField body="email" type="string" required>
  The registered email address of the account.
</ParamField>

<ParamField body="password" type="string" required>
  The account password.
</ParamField>

### Example request

```json title="POST /api/auth/login"
{
  "email": "user@globetrotter.com",
  "password": "password123"
}
```

### Response fields

<ResponseField name="data" type="object">
  The authenticated user's profile.

  <Expandable title="data fields">
    <ResponseField name="id" type="string">UUID of the authenticated user.</ResponseField>
    <ResponseField name="email" type="string">Registered email address.</ResponseField>
    <ResponseField name="name" type="string">Display name.</ResponseField>
    <ResponseField name="role" type="string">`USER` or `ADMIN`.</ResponseField>
  </Expandable>
</ResponseField>

### Example response

```json title="200 OK"
{
  "success": true,
  "data": {
    "id": "1",
    "email": "user@globetrotter.com",
    "name": "Alex Traveler",
    "role": "USER"
  },
  "message": "Login successful",
  "error": null
}
```

### Error responses

| Status | Condition |
|--------|-----------|
| `401`  | Email not found or password incorrect |

```json title="401 Unauthorized"
{
  "success": false,
  "data": null,
  "message": null,
  "error": "Invalid credentials"
}
```

## POST /api/auth/demo-login

Instantly log in as one of GlobeTrotter's built-in demo accounts — no registration required. Use this endpoint to explore the full feature set without creating a real account. A session cookie is set on success.

<Tip>
  Demo accounts are pre-seeded with sample trips, budget data, and saved destinations so you can explore every part of GlobeTrotter immediately after signing in.
</Tip>

### Request body

<ParamField body="type" type="string" required>
  Which demo account to sign in as. Accepted values:
  - `"user"` — signs in as `user@globetrotter.com` (role: `USER`)
  - `"admin"` — signs in as `admin@globetrotter.com` (role: `ADMIN`)
</ParamField>

### Demo credentials reference

| Type | Email | Password | Role |
|------|-------|----------|------|
| `user` | `user@globetrotter.com` | `password123` | `USER` |
| `admin` | `admin@globetrotter.com` | `password123` | `ADMIN` |

### Example requests

<Tabs>
  <Tab title="Demo User">
    ```json title="POST /api/auth/demo-login"
    {
      "type": "user"
    }
    ```
  </Tab>
  <Tab title="Demo Admin">
    ```json title="POST /api/auth/demo-login"
    {
      "type": "admin"
    }
    ```
  </Tab>
</Tabs>

### Response fields

<ResponseField name="data" type="object">
  The demo user object.

  <Expandable title="data fields">
    <ResponseField name="id" type="string">ID of the demo user (`"1"` for user, `"2"` for admin).</ResponseField>
    <ResponseField name="email" type="string">Demo account email address.</ResponseField>
    <ResponseField name="name" type="string">Demo account display name.</ResponseField>
    <ResponseField name="role" type="string">`USER` or `ADMIN` depending on the `type` supplied.</ResponseField>
  </Expandable>
</ResponseField>

### Example response

```json title="200 OK — demo user"
{
  "success": true,
  "data": {
    "id": "1",
    "email": "user@globetrotter.com",
    "name": "Alex Traveler",
    "role": "USER"
  },
  "message": "Demo login successful",
  "error": null
}
```

### Error responses

| Status | Condition |
|--------|-----------|
| `400`  | `type` is missing or not one of `"user"` / `"admin"` |

## POST /api/auth/logout

End the current session and clear the NextAuth session cookie. After a successful logout, all subsequent requests to protected endpoints will return `401 Unauthorized` until the user logs in again.

### Request body

No request body is required.

### Example response

```json title="200 OK"
{
  "success": true,
  "data": null,
  "message": "Logged out",
  "error": null
}
```

<Note>
  If you are building a client-side integration, call `signOut()` from `next-auth/react` instead of hitting this endpoint directly. The NextAuth client handles cookie clearing and redirect automatically.
</Note>
